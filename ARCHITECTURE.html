Module → Core: RewardEvent Contract
Modules never import from core/. Every POST /answer returns this shape. The Core gateway processes it.
# Every module's answer endpoint returns a RewardEvent dict
RewardEvent = {
    "correct":          bool,
    "coins":            int,           # 0–3 based on speed + difficulty
    "xp":               int,           # 5–15 per correct answer
    "badges_earned":    list[str],     # namespaced: "math.moltiplicazioni:speed-demon"
    "streak_activity":  bool,          # True = counts toward today's streak
    "srs_updated":      bool,
    "module_data":      dict,          # module-specific (heatmap update, planet unlock, …)
}

# Core gateway (app.py) receives this and calls:
core.models.apply_reward(user_id, event)
# → updates user_wallet, user_streaks, user_badges
# → no module code ever touches core tables directly
Three-Layer Module Activation Model
Layer 1 — Global (Operator)
Table: module_tokens
Question: Is Blueprint registered?
Scope: Everyone or no one
Restart: Required
Actor: Platform operator

Prerequisite for all access. A module that isn't registered here cannot be used by anyone.
Layer 2 — Organisation (School)
Tables: organizations + org_module_access
Question: Has the school purchased it?
Scope: All org members
Restart: Not required — instant
Actor: School admin redeems token

One token grants access to every current and future member of the organisation.
Layer 3 — Per-User (Individual)
Tables: user_access_tokens + user_module_access
Question: Has this user purchased it?
Scope: That user only
Restart: Not required — instant
Actor: User redeems personal token

Free modules auto-granted at registration. Paid modules require a personal token.
Access = Layer 1 registered AND (free:true OR org has access OR user has access)
GET /api/v1/modules/active runs this three-condition check for the current user on every request. Guests see only free:true modules. New student joining a school inherits all org Layer 2 grants automatically.

  • users— id, username, email, password_hash, role
  • refresh_tokens— token_hash, expires_at, revoked
  • user_wallet— coins, xp, level
  • user_streaks— current/longest streak, shields

  • organizations— Layer 2: school/group entity

Design Decisions — 15 Gaps Identified & Resolved

✓ Blueprint registration is static

Flask cannot register Blueprints at runtime. Decision: token activation sets pending_restart=True; module goes live after next deploy. Frontend shows "coming soon" state. This is documented, not hidden.

✓ JWT vs Flask-Login conflict

JWT is already implemented in app.py. Decision: keep JWT (stateless, already working). Remove Flask-Login from requirements. Add POST /api/v1/auth/refresh and refresh_tokens table.

✓ Module → Core write mechanism

Modules cannot import from core/. Decision: every POST /answer returns a RewardEvent dict. The Core API gateway calls core.models.apply_reward(). Zero coupling.

✓ srs.py imports database.py

Decision: refactor srs.py to pure functions only (no DB imports). Each module's models.py handles SRS table reads/writes. The algorithm is shared; the storage is not.

✓ Guest → registered user migration

POST /api/v1/auth/register accepts optional guest_progress payload. Merges: planet unlocks (if boss score provided) + SRS state. Coins/XP not migrated (anti-abuse). core.js sends this automatically.

✓ SQLite per-request connections

Decision: use Flask's g object — one connection opened per request, closed in @app.teardown_appcontext. Enable WAL mode (PRAGMA journal_mode=WAL) for concurrent reads. Migrate to PostgreSQL before public launch.

✓ Universal game.html injection

Each module manifest includes "ui_script": "/static/modules/<id>/game.js". game.html reads the active module from the URL, fetches its manifest, then import()s the declared script dynamically. No pre-bundling needed.

✓ No user roles in schema

Decision: add role TEXT DEFAULT 'student' to users table now. Values: student | teacher | parent | admin. Teacher/parent dashboards are Phase 3; the schema is ready.

✓ Badge ID namespace collision

Badge IDs stored as "<module_id>:<slug>" (e.g. "math.moltiplicazioni:speed-demon"). The UNIQUE(user_id, badge_id) constraint now correctly scopes per module. No cross-module collision possible.

✓ No module health endpoint

Added GET /api/v1/modules/health. Returns status for every known module: registered (live), broken (import failed — with error message), pending_restart (token inserted, not yet loaded).

✓ No API versioning

All endpoints now use /api/v1/ prefix. Breaking changes will use /api/v2/. Old versions deprecated with a sunset header before removal.

✓ module_tokens seeding not described

database.init_db() seeds built-in module rows with INSERT OR IGNORE INTO module_tokens (module_id, built_in) VALUES (...). Safe to run on every startup — idempotent.

✓ italiano_verbi breaks imports

verbi_data.py stays at the project root during Phase 1. The italiano_verbi module imports it from there. File only moves into the module folder when the Italian module is fully ported (Phase 2).

✓ No JWT refresh / expiry handling

Access tokens expire in 1h. core.js intercepts 401 responses, calls POST /api/v1/auth/refresh with the stored refresh token, retries the original request. If refresh also fails, redirects to login.

⚠ Concurrent session conflicts

Two devices reviewing the same SRS fact simultaneously: last write wins. last_updated column added to all SRS tables. Conservative merge (take lower quality score) planned for v2 — acceptable limitation for v1.
